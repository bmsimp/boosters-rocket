# Booster Rocket v1 — Plan Roadmap

**Spec:** `docs/superpowers/specs/2026-11-06-booster-rocket-v1-design.md`
**Visual system:** `DESIGN.md`, `design/reference/` (parent home, Display page, `booster.css`, `display.js`)

The v1 spec covers several subsystems. Each gets its own plan, and each plan ends with working,
tested software. Plans are written one at a time, just before they are executed, so each can use
what the previous one actually built.

| Plan | Delivers | Depends on | Status |
|---|---|---|---|
| **0. Verification spikes** | Answers to the spec's §15 questions, using throwaway scripts under `spikes/` (deleted after). Needs real accounts: Intuit sandbox, an Entra External ID trial tenant, a local Documenso | Nothing; runs alongside Plan 1 | To write |
| **1. Foundation** | Next.js app, Postgres, permissions system, staff and parent sign-in doors, first admin, roles and staff screens, club theming and display modes, app shell, audit log, CI | Nothing | **Written:** `2026-11-07-plan-1-foundation.md` |
| **2. QuickBooks connection and money** | OAuth connect, token health, roster cache and nightly refresh, family balances, open invoices with Pay links, offline state, reconciliation screen | Plan 1; Plan 0 InvoiceLink answer | To write |
| **3. Roster and guardians** | Staff roster screens writing to QuickBooks, guardian management, Entra External ID provisioning through Graph, parent contact edits, confirmed email change, write queue | Plans 1–2; Plan 0 Graph sign-in answer | To write |
| **4. Season steps, requirements and forms** | Seasons, steps, requirement kinds (form, payment, checklist), waivers, the live season ruler, Documenso forms with consent, embedding, webhooks and evidence | Plans 1–3; Plan 0 Documenso answers | To write |
| **5. Volunteering** | Events, shifts, sign-up and cancellation, reminders with calendar files, self check-in, credit, buy-out invoices | Plan 4; Plan 0 buy-out invoice answer | To write |
| **6. Operations** | Production Docker image, GHCR publishing with a `stable` tag, health page, backups and restore runbook, first-deployment, Intuit, External ID and Documenso runbooks, end-to-end sandbox smoke test | Plans 1–5 | To write |

Plan 0's results can change Plans 2–5. If a spike fails, the affected spec section is revised
before that plan is written (spec §15).
